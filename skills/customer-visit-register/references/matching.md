# 提取事实与客户匹配

## 事实提取

针对14类字段保存“原文短证据→拟提取值→目标字段”。没有证据的值保持未知，不能填成空值提交。有效但不属于结构化范围的拜访过程，可留在历史追加文字中，不再建其他字段映射。

提取前按 [转写勘误词库](keyword-corrections.md) 生成校正候选。原词与规范词同时保留；校正品牌、产品、型号、客户或人物后会改变拟写入值时，必须在确认方案中显式展示。词库命中本身不是充分证据。

识别说话者、否定、时间和条件。例如“我介绍了拉篮，老板只想试铰链”只能把铰链作为意向；“以后有单试试”不等于已合作；“高意向”不能推定全品合作。

今天/昨天/下周需以明确的拜访语境日期及时区解释。旧转写的上传时间不是拜访时间。日期或跟进人缺失时询问，不把操作者自动设为业务员。

规范化空白、全半角和标点可用于检索，但保留原词。人名、产品和客户名疑似同音错字时结合词库、知识库实体和表格选项提候选，不悄悄纠正。经确认的客户别名绑定客户记录ID及地区，不把同一简称全局指向一个客户。

## 查重和匹配

1. 用户提供客户记录链接时，核对目标表及客户身份。
2. 按完整客户名和已确认别名检索；对“区域－集散地－客户名”拆分检索。
3. 检查地区、集散地、客户类型和已知背景是否相符。名称相同但地区不同仍是多个候选。
4. 近似名称仅用于候选召回，不能仅凭相似度强行更新。
5. 全表搜索无候选才提议新增；检索不完整时标记未知，不把看不到的客户视为不存在。

如果业务背景仍无法唯一定位，展示少量候选及区别，用户选择后再生成确定写入方案。连锁门店、同品牌不同工厂不可自动合并。多条重复旧记录不自动删除或同步修改，先由用户指定。

同一转写中多个客户拆分计划；同一客户的多个真实拜访事件按时间保留并合并到一个客户更新计划。重复执行同一份转写不产生新拜访事件；疑似重复但措辞有变化时提示核对，不自动丢弃可能真实的第二次拜访。
